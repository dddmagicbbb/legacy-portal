# 04. 매직넘버 - 숫자 리터럴의 의미 추정과 대체 이름

> **이 문서는 무엇인가** - 프로덕션 코드에서 의미 설명 없이 쓰인 숫자 리터럴(매직넘버)을 모두 찾아, 주석·사용 맥락·화면(index.html)으로 각 숫자의 의미를 추정하고 enum·상수로 바꿀 이름을 제안한 진단 문서다.
> **왜 보는가** - `status == 1`, `role >= 2` 같은 숫자는 코드만 봐서는 뜻을 알 수 없고, 같은 숫자가 곳곳에 흩어져 있어 규칙이 바뀌면 빠짐없이 고치기 어렵다(Primitive Obsession). 숫자마다 의미와 사용처를 먼저 확정해 두어야 enum 으로 바꿀 때 **DB 에 저장되는 정수값과 API 가 받는 숫자는 그대로 유지**하면서 안전하게 이름만 붙일 수 있다.

> 측정 기준: 커밋 `802cbe5`, `src/main/java` 전체 + 참고용 `src/main/resources/static/index.html`.
> 의미의 **근거** - 🅒 코드 주석에 명시 · 🅤 화면(index.html) 라벨 · 🅢 사용 맥락으로 추정.

| 숫자 | 의미 | 근거 | 제안 상수 | 사용 위치 |
|---|---|:---:|---|---|
| `1000000` (100만원) | 지출 결재를 **상신할 때 우선순위를 높음으로 올리는 기준** | 🅒 | `HIGH_PRIORITY_EXPENSE_THRESHOLD` | `ApprovalService.java:94` |
| `10000000` (1,000만원) | 금액 등급 **S** 하한 | 🅒 | `GRADE_S_MIN_AMOUNT` | `:184` |
| `1000000` (100만원) | 금액 등급 **A** 하한 | 🅒 | `GRADE_A_MIN_AMOUNT` | `:185` |
| `100000` (10만원) | 금액 등급 **B** 하한 | 🅒 | `GRADE_B_MIN_AMOUNT` | `:186` |

- **⚠ 함정:** `1000000` 이 두 번 나오지만 **의미가 다르다**(우선순위 상향 기준 vs A등급 하한). 값이 같다고 상수 하나로 합치면, 나중에 한쪽 정책만 바꿀 때 다른 쪽까지 바뀐다. **상수는 의미 단위로 따로** 만든다.
- 금액 등급 S/A/B/C 자체도 문자열 매직값이다 - `ApprovalAmountGrade` enum 후보 (반환 문자열 `"S"` 등은 유지).
- 위치 제안: 이 규칙들은 `Approval` 의 데이터로 계산하므로 서비스가 아니라 도메인(`Approval`·enum)으로 옮기는 것이 자연스럽다 (Feature Envy 해소).

## 5. 리팩토링 방향 (개선 대상 - 차후)

| 순서 | 대상 | 방법 |
|:---:|---|---|
| 1 | M1~M8 도메인 코드값 | 도메인 이름 enum(`ApprovalStatus`, `UserRole` …)에 `code` 필드를 두고, `AttributeConverter` + `@Convert` 로 **DB 에는 기존 정수 그대로 저장** |
| 2 | M2 action | 컨트롤러·서비스 내부에서 `ApprovalAction.fromCode(int)` 로 변환. **API 요청은 계속 숫자**, public 시그니처 `processApproval(Long, Long, int, String)` 유지 |
| 3 | M5 `role >= 2` | `UserRole` 에 권한 판정 메서드 - 숫자 크기·ordinal 비교 제거 |
| 4 | M9 금액 기준 | 의미별 상수로 분리, 규칙은 도메인으로 이동 |

### 반드시 지킬 것 (보존 대상)

- **DB 저장값:** 0/1/2/3/9 등 기존 정수 그대로. `@Enumerated(STRING)`(문자 저장)·`@Enumerated(ORDINAL)`(9 → 4 로 어긋남) **금지**.
- **API 형식:** 요청의 `type`·`priority`·`action`, 응답의 `status`·`type`·`priority`·`role` 은 **계속 숫자**로 주고받는다 (화면 `index.html` 이 숫자에 의존).
- **알 수 없는 값의 동작:** 정의 밖의 코드도 레거시처럼 저장되고(`type`·`priority`), 무시되며(`action`), `"알수없음"` 라벨을 받는다(`statusLabel`). enum 변환이 예외를 던지면 동작 변경이다.
- **특성화 테스트:** enum 도입 후에도 테스트는 **기존 정수 리터럴(0/1/2/3/9)로 호출·검증**한다.
