# 08. 리팩토링 백로그 - 우선순위 순 작업 목록

> **이 문서는 무엇인가** - 진단 06(영향 × 범위 → 처리 순서)과 07(영향 × 수정난이도 → 심각도 ★)의 채점을 합쳐, 스멜 16종을 **실제로 한 번에 하나씩 수행할 작업 단위(백로그 항목)** 로 쪼개고 우선순위 순으로 늘어놓은 문서다. 항목마다 선행 조건, 크기, 완료 조건(DoD), 지켜야 할 보존 대상을 적었다.
> **왜 보는가** - 리팩토링은 "작은 단계 → 테스트 green → 커밋"을 반복할 때만 안전하다. 스멜 목록만으로는 어디서 시작해 어디서 멈출지 알 수 없다. 백로그는 **다음에 할 일 하나**와 **그 일이 끝났다고 말할 기준**을 정해 주어, 큰 부채(★★★★★)를 위험 없이 나눠 갚게 해 준다.

## 1. 우선순위 결정 규칙

1. **안전망 먼저** - 특성화 테스트(S01)가 없는 코드는 손대지 않는다.
2. **빠른 성과 다음** - 영향은 크고 쉬운 것(S04, ★2)을 먼저 해서 이후 작업을 쉽게 만든다.
3. **큰 부채는 쪼갠다** - ★4~5(S03·S02)는 커밋 하나에 기법 하나만 적용하는 하위 항목으로 나눈다.
4. **의존 순서를 지킨다** - enum(S03)이 있어야 분기·도메인 이동(S02·S06)의 코드가 읽히고, API 테스트가 있어야 DTO(S07)를 바꿀 수 있다.
5. **★1 은 따로 계획하지 않는다** - 상위 항목을 하면서 함께 정리하고, 남은 것만 마지막에 모은다.
6. **S12(조용한 실패)는 백로그 밖** - 동작 변경이므로 리팩토링 완료 후 재설계 단계에서 다룬다.

크기: **S** = 커밋 1개 · **M** = 커밋 2~3개 · **L** = 커밋 4개 이상
상태: ⬜ 미착수 · 🔄 진행 중 · ✅ 완료 (진행 기록은 5절)

## 3. 항목 상세

### B01. 특성화 테스트 작성 — S01 · ★★★★☆ · L

현재 동작을 **옳고 그름 판단 없이** 그대로 고정한다. 이후 모든 항목의 안전망.

| 하위 | 범위 | 고정할 동작 |
|---|---|---|
| B01-1 | `ApprovalService.processApproval` | 상신·승인·반려·취소 × (성공 / 조용한 무시). 무시 케이스: 없는 결재·사용자, 잘못된 상태, 결재자·기안자 아님, 권한 없음(role 1), 정의 밖 action(예: 5) |
| B01-2 | `ApprovalService` 나머지 | `create`(status 0, urgent → priority 3), 지출 100만원↑ 상신 시 priority 3, `statusLabel`(정의 밖 → "알수없음"), `amountGrade` 경계값(99,999 / 100,000 / 999,999 / 1,000,000 / 10,000,000), `myDrafts`·`myInbox` |
| B01-3 | `NoticeService` | 생성(status 0), 게시(role≥2 & status 0), 권한 없음·이미 게시 → 무시, 긴급 공지 = 전 직원 수만큼 메일, `statusLabel` |
| B01-4 | `ScheduleService` | 생성 검증 실패 3종 → `null`, 시간 겹침 → `null`, 취소(9) 일정은 겹침 제외, 경계(끝 = 시작)는 겹치지 않음, `confirm` 본인·예정만 |
| B01-5 | API (`MockMvc`) | `/api/approvals` 생성·처리·목록, `/api/users` - **요청 JSON·응답 JSON 필드와 숫자 코드**, 기본값(`amount`·`urgent`·`reason` 생략) |

- **작성 방식:** 서비스를 `new` 하지 말고 **스프링 컨텍스트에서 주입**받는다(`@SpringBootTest` 등). 그래야 B02 에서 생성자가 바뀌어도 테스트 본문을 고칠 일이 없다.
- **메일·로그 검증:** 지금은 `System.out` 캡처로 고정한다 (B02 이후에도 출력은 같으므로 그대로 green).
- **규칙:** 기대값은 정수 리터럴(0/1/2/3/9). 이름은 영어, 메서드명만 한글 시나리오 (예: `권한없는_사원이_승인하면_무시된다()`).
- **DoD:** 전 테스트 green · 이후 리팩토링 중 **본문 수정 0건**.

### B02. 메일·감사 로거 DIP + 생성자 주입 — S04 · ★★☆☆☆ · S

| 단계 | 작업 |
|---|---|
| 1 | `common` 에 `MailSender`·`AuditLogger` 인터페이스 추출 (`send(to, subject, body)`·`write(line)` 그대로) |
| 2 | `SmtpMailSender`·`FileAuditLogger` 가 구현 + `@Component` |
| 3 | 세 서비스의 필드 `new` 제거 → 생성자 주입 (5곳) |

- **보존:** 출력 문자열·발송 조건·횟수 동일. public 메서드 시그니처 동일.
- **DoD:** `new SmtpMailSender`/`new FileAuditLogger` 검색 결과 0 · B01 green.
- **덤:** 이후 **새로 추가하는** 테스트는 가짜 구현(`RecordingMailSender` 등)을 쓸 수 있다. 기존 B01 테스트는 그대로 둔다.

### B03. 매직넘버 → 도메인 enum + Converter — S03 · ★★★★☆ · L

| 하위 | 작업 | 주의 |
|---|---|---|
| B03-1 | `ApprovalStatus`(0/1/2/3/9) + `AttributeConverter`, 엔티티 `@Convert` | `@Enumerated` 금지. 정의 밖 코드 처리 방식 결정(아래) |
| B03-2 | `ApprovalAction`(1/2/3/9) - DB 저장 없음, `processApproval` 내부에서만 변환 | **status 와 별개 enum.** 정의 밖 action 은 무시 유지 |
| B03-3 | `ApprovalType`(1~4) · `ApprovalPriority`(1~3) | 검증 없이 5 등도 저장되던 동작 유지 |
| B03-4 | `UserRole`(1~3) + `hasApprovalAuthority()` 등 권한 메서드 | `role >= 2` 를 ordinal 비교로 옮기지 않는다 |
| B03-5 | `NoticeStatus` · `NoticeCategory` · `ScheduleStatus` | 9(내림·취소) 포함 |
| B03-6 | 금액 기준 상수 4개 (의미별 분리) | `1000000` 두 의미를 합치지 않는다 |

- **정의 밖 코드:** 지금은 아무 정수나 저장·조회된다. Converter 가 예외를 던지면 동작 변경이므로, 하위 항목 시작 전에 B01 로 "정의 밖 값"의 현재 동작을 확인하고 **그 동작을 유지하는 방식**(엔티티 필드는 정수 유지 + enum 조회 메서드 등)을 고른다.
- **덤:** `statusLabel` 의 라벨을 enum 으로 옮기면 S11·S13 일부가 해소된다 (반환 문자열 동일).
- **DoD:** 서비스·엔티티에 상태·유형·역할 비교용 정수 리터럴 0건 · DB 값 동일 · B01 green.

### B04. `processApproval` 분해 — S02 · ★★★★★ · L

가장 비싼 부채. **커밋마다 기법 하나.**

| 하위 | 작업 | 기법 |
|---|---|---|
| B04-1 | 분기별 private 메서드 추출: `submit` · `approve` · `reject` · `cancel` | 메서드 추출 |
| B04-2 | `processApproval` 은 조회 가드 + action 별 위임만 남김 | 위임 |
| B04-3 | 각 메서드의 중첩 조건을 가드 절로 평탄화 (목표 중첩 ≤ 2) | 가드 절 |
| B04-4 | 지역변수 이름 개선: `d`→`approval`, `u`→`user`, `s`→`status`, `proc` 제거, `tmp`·`a` 등 | 이름 바꾸기 (S09) |

- **보존:** `processApproval(Long id, Long userId, int action, String reason)` 시그니처, `/api/approvals/{id}/process` 하나로 유지. 조건 불충족 시 **조용히 무시**. 메일·로그의 순서와 문구.
- **DoD:** `processApproval` ≤ 15줄 · 분기 메서드 각 ≤ 20줄 · 중첩 ≤ 2 · B01 green.
